    Class CreatejsMovieClip

    inherited createjs.MovieClip

    mask is a plain data property on the real createjs.DisplayObject, but this wrapper must intercept get/set to route the assigned value into the Pixi mirror. See the class-level comment on CreatejsShape for why a prototype accessor safely intercepts it despite TS2611/TS2416.

    advance

    • advance(time?: number): void

      Advances the timeline (delegated to the original createjs implementation) and dispatches the custom frame events right after the frame changes, before the children are ticked — the same timing the previous self-managed walk provided.

      framerate is fixed at -1 and the driver never passes a delta, so one call always advances exactly one frame (determinism lives with the caller).

    settleForPixi

    • settleForPixi(): void

      Settles the tree for drawing without playing on — what createjs does to each clip when the stage draws (MovieClip.draw -> _updateState): synched and single-frame clips are placed at the frame their parent gives. A clip waiting to start over (an independent clip reset when its parent placed it again, _rawPosition -1) is shown at its first frame the way createjs shows a new clip (_renderFirstFrame: no frame script, the playhead left as it was), so that it starts on the next frame played, as in the Animate template, where createjs draws only after a tick (a draw's _updateState would start it at once, a frame ahead). Children are settled after their parent, in the resolve phase's order. Used right before Pixi draws a tree whose timelines moved between frames (CreatejsController.flushForRender).
